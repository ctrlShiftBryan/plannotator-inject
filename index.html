Componentize the Dynasty Screens

This PR splits the monolithic screens module into reusable components and wires them through the new navigation stack.

Overview

The screens previously lived in a single 2,000-line file. We extract each screen into its own component and introduce a shared ScreenShell wrapper that owns the header, scroll container, and safe-area insets.

Goals

Reduce coupling, make each screen independently testable, and unblock the upcoming theming work. No behavior changes are intended in this PR.

Key Changes

New components

We add ScreenShell, RosterCard, and StatPill. Each is a pure presentational component that takes its data via props and emits intent callbacks.

ScreenShell contract

It accepts a title, an optional onBack, and children. Internally it renders the navigation chrome.

function ScreenShell({ title, onBack, children }) {
  return (
    <View style={styles.shell}>
      <Header title={title} onBack={onBack} />
      <ScrollView>{children}</ScrollView>
    </View>
  );
}

How to verify

Manual verification in the browser

Open each screen, confirm the header renders, and check that back navigation pops the stack. Then run yarn test screens.
